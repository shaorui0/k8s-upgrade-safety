# testenv: the synthetic fleet

`fleet.yaml` is generated by `gen_fleet.py` (`python3 testenv/gen_fleet.py > testenv/fleet.yaml`). Everything in it is invented: generic cluster names, fake `ami-synth-*` ids, no real versions of anything but the public Kubernetes minor numbers. Each cluster is a plain data structure the simulator mutates in memory; nothing here talks to a network.

| Cluster | Stage | Type | What is special |
|---|---|---|---|
| `dev-1` | dev | dev-staging | clean |
| `preprod-1` | preprod | dev-staging | a node evicts in 540 s **and** the cluster carries `drain_timeout_s: 600`: the flagged exception that passes |
| `prod-canary` | prod-canary | workload | clean; Kafka and MySQL nodes with healthy PDBs; flag 600 |
| `prod-east` | prod | workload | **F1** one etcd follower 2000 entries behind: `check` fails |
| `prod-west` | prod | workload | **F3** MySQL node's PDB allows zero disruptions: the canary (first, stateful) node's drain blocks, no forced drain |
| `prod-south` | prod | workload | **F2** the target CCM rollout is unhealthy: addon layer stops at CCM |
| `prod-eu` | prod | workload | **F4** a node evicts in 540 s with the default 300 s timeout: worker batch stops, the fix is the 600 s flag |
| `prod-north` | prod | workload | **F5** the second master's apiserver never passes `/readyz` or LB membership: control plane stops before controller-manager is touched |
| `mgmt-1` | management | management | clean; always last |

The `faults:` list at the bottom of the YAML is the ground truth: cluster, kind, and the step expected to stop. Tests assert both that the fault is really in the data and (from c0003 on) that the pipeline stops at that step.

Faults are data fields (`target_rollout_healthy`, `readyz_after_upgrade`, `eviction_s`, PDB numbers, `raft_index`). No code branches on a cluster name.
